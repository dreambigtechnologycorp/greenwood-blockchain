# Greenwood v0.1.0-alpha.1

Experimental source-only prerelease of the Greenwood PHP reference implementation. No native binaries, runtime distributions, container images, or deployment bundles are included. This is not a production-ready or independently audited release.

## Included

- Fixed-validator BFT consensus, canonical transactions, finalized block history, and recoverable SQLite state.
- Deterministic Wasmtime smart contracts and finalized read-only contract queries.
- Public RPC, authenticated operator controls, and digest-pinned OCI compute through containerd.
- Registry authorization, signed assignments, provider recovery, and guarded deployment tooling.

## Verification

Validated with Homebrew PHP 8.5.12 on macOS ARM64:

- Existing PHP source suite: 577 passed, 2 platform checks skipped.
- Existing contract suite: 28 passed (1,072 assertions), using Wasmtime 48.0.1 and its C headers.
- 13 local service regression scripts passed, including real mutual TLS loopback checks.
- 32 local Ansible regression tests passed.
- 4 source-packaging tests and 4 independent protocol/vector verification scripts passed.
- The publishable source credential/path check reported no flagged files.

The two PHP skips concern the Linux mkfs.ext4 diagnostic and the native gRPC image-status contract. Existing PHP 8.5 deprecations remain. ARM/Linux provider, live containerd/runc/EROFS, bare-metal installation, reboot acceptance, and physical end-to-end deployment validation were not performed for this release.

## Requirements and limits

PHP ^8.5 and the extensions declared in composer.json are required. Run composer install from the extracted source tree. Contract execution additionally requires the pinned Wasmtime 48.0.1 runtime and PHP FFI; the contract layout checks also require its C headers. Provider operation requires a separately provisioned Linux runtime and the prerequisites in docs/linux-execution-manifest.md.

Dependencies and native runtimes are not bundled. Generated PHP protobuf bindings are included; the pinned upstream containerd submodule contents are not. The manifest records its revision. The Python deployment CLI is a separate repository and release artifact.

Frozen signing material in protocol test vectors is public test data and must never be reused for operational identities. Supply your own protected keys, trust material, policies, inventory, and runtime state outside source control.

## Assets

Download the commit-named source .tar.gz together with manifest.json and SHA256SUMS. Verify the downloaded archive and manifest with:

```sh
shasum -a 256 -c SHA256SUMS
```

SHA-256 checksums verify file integrity; no release-signing identity or signature is claimed.
